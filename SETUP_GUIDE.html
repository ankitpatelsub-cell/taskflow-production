2. Quick Start with Docker Compose

The fastest path to a running production stack. All services start in a single command.

Step 1 — Clone & enter the repo

git clone https://github.com/your-org/taskflow-production.git
cd taskflow-production

Step 2 — Create your environment file

cp .env.production.example .env
nano .env   # fill in required values (see §3)

Step 3 — Build the frontend

cd frontend
npm install
VITE_API_URL=https://your-domain.com/api npm run build
cd ..
The built files land in frontend/dist/. nginx serves them directly from there.

Step 4 — Start the stack

docker compose up -d
docker compose logs -f

Step 5 — Run database migrations

docker compose exec backend node -e "
const { runMigrations } = require('./src/config/db');
runMigrations().then(() => { console.log('Done'); process.exit(0); });
"

Step 6 — Verify health

curl https://your-domain.com/api/health
# Expected: {"status":"ok","db":"connected"}
Tip: To stop without losing data: docker compose stop. To destroy everything including volumes: docker compose down -v (destructive — deletes DB data).

4. Manual (Non-Docker) Setup

If you prefer to run without Docker (e.g., existing server, VPS, managed DB).

Install Prerequisites

# Node.js 22
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo bash -
sudo apt-get install -y nodejs

# PostgreSQL 16
sudo apt-get install -y postgresql-16

# Nginx
sudo apt-get install -y nginx

Set up the Database

sudo -u postgres psql <<'SQL'
CREATE USER tick WITH PASSWORD 'your-strong-password';
CREATE DATABASE tickdb OWNER tick;
GRANT ALL PRIVILEGES ON DATABASE tickdb TO tick;
SQL

Install Backend Dependencies

cd backend
npm ci --only=production

Set Up Environment

cp ../.env.production.example .env
# Edit .env with your values
nano .env

Run as a systemd Service

sudo tee /etc/systemd/system/tick-backend.service <<'EOF'
[Unit]
Description=Tick Backend API
After=network.target postgresql.service

[Service]
Type=simple
User=www-data
WorkingDirectory=/opt/tick/backend
EnvironmentFile=/opt/tick/backend/.env
ExecStart=/usr/bin/node index.js
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl enable tick-backend
sudo systemctl start tick-backend

Build and Deploy Frontend

cd frontend
npm ci
VITE_API_URL=https://your-domain.com/api npm run build
sudo cp -r dist/* /var/www/tick/

Nginx Configuration

sudo cp nginx.conf /etc/nginx/sites-available/tick
sudo ln -s /etc/nginx/sites-available/tick /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx

5. Database Migrations

Migrations live in backend/src/migrations/ and run automatically on startup (in Docker). For manual execution:

# With Docker
docker compose exec backend node -e "
const { runMigrations } = require('./src/config/db');
runMigrations().then(() => { console.log('Migrations complete'); process.exit(0); })
.catch(e => { console.error(e); process.exit(1); });
"

# Without Docker (from backend/ directory)
node -e "
const { runMigrations } = require('./src/config/db');
runMigrations().then(() => process.exit(0)).catch(e => { console.error(e); process.exit(1); });
"

Migration Files (in order)

FilePurpose
001_initial_schema.sqlCore tables: users, projects, tasks, time_logs
002_...Auth: refresh_tokens, email verification
003_...Notifications, activity logs
004_...Sprints, epics
005_...Comments, reactions, mentions
006_...Custom fields
007_...Webhooks, audit logs
008_...Subscriptions / plans
009_...Share links
010_workspaces.sqlWorkspaces / org model
011_verify_existing_users.sqlMark pre-existing users as email-verified
Migrations are idempotent — safe to run multiple times. They use IF NOT EXISTS and DO $$ BEGIN ... EXCEPTION WHEN duplicate_column ... guards.

6. First Login & Initial Configuration

Create the First Admin User

The first user to register via POST /api/auth/register (or the UI signup page) gets the member role by default. Promote them to super_admin:

# With Docker
docker compose exec db psql -U tick -d tickdb -c \
  "UPDATE users SET role='super_admin' WHERE email='your@email.com';"

Configure Your First Workspace

  1. Log in at https://your-domain.com
  2. A default workspace is created automatically when you first register
  3. Click the workspace name in the sidebar → Workspace Settings
  4. Rename it, set your organization name, and invite team members

Plan Configuration

Insert a subscription record to unlock plan limits:

# Set the plan (free/pro/team)
docker compose exec db psql -U tick -d tickdb -c \
  "INSERT INTO subscriptions (id, plan, status) VALUES (gen_random_uuid(), 'pro', 'active')
   ON CONFLICT DO NOTHING;"

7. Integrations

Email (SMTP / SendGrid)

  1. Sign up at SendGrid (free tier: 100/day) or use any SMTP provider
  2. Create an API key with Mail Send permission
  3. Set in .env: SMTP_HOST=smtp.sendgrid.net, SMTP_PORT=587, SMTP_USER=apikey, SMTP_PASS=SG.xxx
  4. Verify by registering a new user — they should receive a verification email

Slack Notifications

  1. Go to api.slack.com/apps → Create New App → From Scratch
  2. Enable Incoming Webhooks → Add to your channel
  3. Copy the Webhook URL
  4. In Tick: Project Settings → Slack → paste the URL → Save → Test

AI Task Breakdown (Anthropic)

  1. Sign up at console.anthropic.com
  2. Create an API key
  3. Set ANTHROPIC_API_KEY=sk-ant-xxx in .env
  4. Restart the backend: docker compose restart backend
  5. In Tick: open any task → click AI Breakdown

Google OAuth

  1. Go to Google Cloud Console → APIs & Services → Credentials
  2. Create OAuth 2.0 Client ID → Web Application
  3. Authorized redirect URI: https://your-domain.com/api/auth/google/callback
  4. Set GOOGLE_CLIENT_ID, GOOGLE_CLIENT_SECRET, GOOGLE_CALLBACK_URL in .env

Webhooks (Outbound)

Tick can POST events to any HTTPS endpoint. Configure per-project under Project Settings → Webhooks. Supported events:

  • task:created, task:updated, task:deleted
  • comment:created
  • project:updated
  • ping (test event)

All payloads include an X-Tick-Signature: sha256=<hex> header when a secret is configured. Deliveries are retried up to 3 times with exponential backoff (1s, 2s, 4s).

8. Security Checklist

  • Change all default secrets in .env (JWT_SECRET, JWT_REFRESH_SECRET, COOKIE_SECRET, POSTGRES_PASSWORD)
  • Set NODE_ENV=production to enable secure cookies, stricter CORS, and HTTP-only flags
  • Enable HTTPS with a valid TLS certificate (Let's Encrypt / Certbot recommended)
  • Firewall: only expose ports 80/443 publicly; block 3001 and 5432 from the internet
  • Set FRONTEND_URL to your exact frontend origin (used in CORS)
  • Verify rate limits are active: curl -I https://your-domain.com/api/health should include RateLimit-* headers
  • Enable 2FA for all admin accounts (Settings → Security → Enable 2FA)
  • Configure SMTP and verify that new users receive verification emails
  • Review file upload limits: default 50 MB, adjust MAX_FILE_SIZE_MB if needed
  • Set up log rotation for nginx and application logs
  • Enable automated daily database backups (see §9)
  • Test disaster recovery: restore from backup on a staging server
Never commit .env to version control. The .env.production.example file contains no real secrets and is safe to commit.

9. Maintenance & Backups

Database Backups

# Manual backup
docker compose exec db pg_dump -U tick tickdb | gzip > tick-backup-$(date +%Y%m%d).sql.gz

# Restore
gunzip -c tick-backup-20260608.sql.gz | docker compose exec -T db psql -U tick tickdb

Automated Daily Backups (cron)

# /etc/cron.daily/tick-backup
#!/bin/bash
cd /opt/tick
docker compose exec -T db pg_dump -U tick tickdb | \
  gzip > /var/backups/tick/tick-$(date +%Y%m%d-%H%M%S).sql.gz
# Keep 30 days
find /var/backups/tick/ -name "*.sql.gz" -mtime +30 -delete

View Application Logs

# All services
docker compose logs -f

# Backend only (last 100 lines)
docker compose logs --tail=100 backend

# Filter for errors
docker compose logs backend 2>&1 | grep '"level":50'

Update Uploaded Files Backup

# The uploads volume is mounted at /app/uploads inside the container
# Back it up alongside the DB
docker run --rm -v tick_uploads:/data -v /var/backups/tick:/backup \
  alpine tar czf /backup/uploads-$(date +%Y%m%d).tar.gz /data

10. Upgrade Procedure

  1. Back up first: Always take a DB backup before upgrading (see §9)
  2. Pull latest code: 
    git pull origin main
  3. Rebuild frontend: 
    cd frontend && npm ci && VITE_API_URL=https://your-domain.com/api npm run build && cd ..
  4. Rebuild and restart services: 
    docker compose build backend
docker compose up -d --no-deps backend
  5. Run any new migrations: 
    docker compose exec backend node -e "
const { runMigrations } = require('./src/config/db');
runMigrations().then(() => process.exit(0));
"
  6. Verify health: 
    curl https://your-domain.com/api/health
For zero-downtime upgrades, run two backend containers behind nginx with upstream and deploy one at a time.

11. Troubleshooting

SymptomLikely CauseFix
Cannot connect to database DB not ready / wrong credentials Check DATABASE_URL; run docker compose ps to verify db is healthy
Login returns 500 JWT_SECRET not set Ensure JWT_SECRET and JWT_REFRESH_SECRET are set in .env
Email not received SMTP not configured Check SMTP_* vars; test with docker compose exec backend node -e "require('./src/services/emailService').sendEmail({to:'test@x.com',subject:'test',html:'test'})"
403 EMAIL_NOT_VERIFIED on all API calls User hasn't verified email Resend verification email or run migration 011_verify_existing_users.sql to mark existing users as verified
429 Too Many Requests Rate limit hit Default: 500 req/15min per IP, 120 req/min per user token. Adjust in index.js if needed.
File upload fails File type not in allowlist or >50 MB Check allowed types in backend/src/utils/fileUpload.js
WebSocket disconnects nginx proxy timeout Verify proxy_read_timeout 86400 and upgrade headers in nginx.conf
AI features return 503 ANTHROPIC_API_KEY not set Set the key in .env and restart backend
Webhook delivery failing Target URL unreachable or non-HTTPS Only HTTPS URLs are accepted. Use the webhook test button to check connectivity.
CORS error in browser FRONTEND_URL mismatch Set FRONTEND_URL exactly matching your frontend origin (no trailing slash)

Getting Debug Logs

# Enable verbose logging
docker compose exec backend sh -c "LOG_LEVEL=debug node index.js"

# Check PostgreSQL slow queries
docker compose exec db psql -U tick -d tickdb -c \
  "SELECT query, calls, mean_exec_time FROM pg_stat_statements ORDER BY mean_exec_time DESC LIMIT 10;"
